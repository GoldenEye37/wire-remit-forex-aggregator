# Phase 1.2: Add Custom Tracing

## Overview

Phase 1.2 focuses on implementing custom distributed tracing throughout the WireRemit Forex Aggregator application. While OpenTelemetry auto-instrumentation provides basic tracing for Flask, SQLAlchemy, and HTTP requests, custom tracing adds business-specific context and visibility into critical operations.

## Objectives

1. **Add Custom Spans**: Create spans for key business operations that auto-instrumentation doesn't capture
2. **Business Context**: Add span attributes that provide business-specific information (provider names, currency pairs, user IDs)
3. **Error Tracking**: Record exceptions and error details in spans for better debugging
4. **Service Mapping**: Create clear service boundaries and operation hierarchies visible in Jaeger
5. **Performance Analysis**: Enable detailed performance analysis of business operations

## Key Concepts

### What is a Span?

A span represents a single operation within a trace. Each span has:
- **Name**: Descriptive operation name (e.g., "fetch_rates_from_provider")
- **Start/End Time**: Duration of the operation
- **Attributes**: Key-value pairs providing context (e.g., provider="CurrencyLayerClient")
- **Status**: Success, error, or unset
- **Events**: Timestamped log messages within the span
- **Parent Span**: Links to parent operation (creates hierarchy)

### What is a Trace?

A trace is a collection of spans that represent a single request or operation flow through the system. Example trace for `/api/v1.0/rates`:
```
HTTP GET /api/v1.0/rates (root span)
├── authenticate_jwt (child span)
├── fetch_rates (child span)
│   ├── fetch_from_currencylayer (child span)
│   ├── fetch_from_exchangerate (child span)
│   └── fetch_from_fixer (child span)
├── aggregate_rates (child span)
└── database_query (child span - auto-instrumented)
```

## Implementation Plan

### 1. Create Tracing Utility Module

Create `app/utils/tracing.py` with:

#### Core Functions:
- `get_tracer()` - Get the application tracer instance
- `create_span(name, attributes)` - Create a new span with context
- `add_span_attributes(span, attributes)` - Add attributes to current span
- `record_span_error(span, exception)` - Record exception in span

#### Decorators:
- `@with_span(name)` - Automatically create span for function
- `@with_provider_span(provider_name)` - Create span for provider operations
- `@with_auth_span()` - Create span for authentication operations

### 2. Add Spans to Rate Fetching Service

**File**: `app/services/rate_fetcher.py`

**Operations to trace**:
1. Overall `fetch_rates()` operation
2. Each provider's `fetch_rates()` call
3. Rate validation operations
4. Retry attempts

**Span attributes to add**:
- `provider.name`: Provider class name
- `provider.priority`: Provider priority level
- `operation.type`: "fetch" or "validate"
- `retry.attempt`: Retry attempt number (if applicable)
- `rate.count`: Number of rates fetched
- `error.type`: Exception type on failure

### 3. Add Spans to Rate Processing Service

**File**: `app/services/rate_processor.py`

**Operations to trace**:
1. Overall `process_all_rates()` operation
2. Individual `process_currency_pair()` operations
3. Rate aggregation calculations
4. Database persistence operations

**Span attributes to add**:
- `currency_pair.id`: Database ID
- `currency_pair.code`: Currency pair code (e.g., "USD/EUR")
- `rate.count`: Number of rates to aggregate
- `aggregation.method`: "median" or other method
- `operation.type`: "process", "aggregate", or "persist"

### 4. Add Spans to Authentication Flow

**File**: `app/decorators.py`

**Operations to trace**:
1. JWT token validation
2. User lookup operations
3. Admin role verification

**Span attributes to add**:
- `auth.type`: "jwt" or "admin"
- `user.id`: User database ID
- `user.role`: User role (if applicable)
- `auth.result`: "success" or "failure"

### 5. Add Spans to API Endpoints

**Files**: `app/api/rates.py`, `app/api/auth.py`, `app/api/admin.py`

**Operations to trace**:
1. Query parameter parsing
2. Business logic execution (use existing spans from services)
3. Response serialization

**Span attributes to add**:
- `http.route`: Specific route template
- `query.base_currency`: Base currency from query params
- `query.target_currency`: Target currency from query params
- `response.rate_count`: Number of rates returned

## Implementation Steps

### Step 1: Create Tracing Utility Module
```python
# app/utils/tracing.py
from opentelemetry import trace
from opentelemetry.trace import Status, StatusCode
from flask import current_app
from functools import wraps
import time

def get_tracer():
    """Get the application tracer instance."""
    if hasattr(current_app, 'tracer'):
        return current_app.tracer
    return trace.get_tracer(__name__)

def create_span(name: str, attributes: dict = None):
    """Create a new span with optional attributes."""
    tracer = get_tracer()
    span = tracer.start_span(name)
    if attributes:
        add_span_attributes(span, attributes)
    return span

# ... more utility functions
```

### Step 2: Add Spans to Services
```python
# Example for rate_fetcher.py
from app.utils.tracing import with_span, add_span_attributes

@with_span("fetch_rates")
def fetch_rates(self, base_currency, target_currency=None):
    span = trace.get_current_span()
    add_span_attributes(span, {
        "currency.base": base_currency,
        "currency.target": target_currency or "all",
    })
    # ... existing logic
```

## Troubleshooting

### Issue: Spans not appearing in Jaeger

**Possible causes**:
1. OTLP exporter not configured correctly
2. Jaeger not receiving traces from collector
3. Tracer not initialized in Flask app

**Solutions**:
```bash
# Check OTLP collector logs
docker-compose logs otel-collector

# Check Jaeger logs
docker-compose logs jaeger

# Verify Flask app tracer
curl http://localhost:5000/health
```

### Issue: Span hierarchy broken

**Possible causes**:
1. Context not propagated correctly
2. Spans created outside of parent context
3. Async operations breaking context

**Solutions**:
```python
# Always use context manager or decorator
with tracer.start_as_current_span("operation"):
    # Your code here
    pass

# Or use decorator
@with_span("operation")
def my_function():
    pass
```

### Issue: Missing span attributes

**Possible causes**:
1. Attributes not set before span ends
2. Invalid attribute types
3. Attribute values are None

**Solutions**:
```python
# Set attributes before span ends
span = trace.get_current_span()
if span.is_recording():
    span.set_attribute("key", "value")

# Filter None values
attributes = {k: v for k, v in attrs.items() if v is not None}
add_span_attributes(span, attributes)
```
